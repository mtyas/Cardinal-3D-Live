# Mixer and audio optimization — 21 October 2026

The user's reported status was **WebRTC unavailable (connection failed; TURN may
be required)**. Those listening tests were using the buffered fallback. CPU and
bandwidth optimization cannot by themselves make that failed ICE connection work.
There is currently no public TURN service configured. Umbrel has no installed TURN
server, and a read-only gateway discovery found no advertised router interface
from which public port availability could be established. No router ports, account
settings, paid services or Umbrel applications were changed.

## Changes

### Separate audio from local visual uploads

The native sender previously read/drained the audio rings even when the shared
socket's outbound queue exceeded 64 KiB, then skipped sending the read audio.
A large visual snapshot could therefore discard source samples independently of
audience bitrate or playback buffer size. This was a concrete loss mechanism,
though its share of the user's outages was not measured.

PCM now has a dedicated authenticated loopback WebSocket, `/performer-audio`.
Control/state/assets retain the original connection. The worker only drains audio
when its own sender is ready and below its backlog limit. Brief backpressure thus
retains samples in the bounded native ring instead of silently discarding them.
Long overload can still overflow that ring, whose existing dropped-sample counter
is checked in integration. Both sockets close with the performance. The audio
endpoint requires the existing private host key, rejects browser origins and
remote addresses, and is not a room member or another audio engine. Legacy local
publishers can still send PCM through the original socket.

### Compact native polling

An opt-in embedded `poll_live` marker keeps native widget stepping at render rate.
Full descriptions refresh at 5 Hz and on generation/topology changes. Intervening
polls return changed parameter values, LED RGB/brightness, visibility and meter
levels, rather than reconstructing geometry, labels, SVG metadata and descriptions.
Value display strings are formatted when the value changes. Structural snapshots
still provide the complete baseline. Older engines without the advertised
`supports_live_values` flag retain the original polling behavior.

The frontend indexes descriptors/controls, merges deltas into the current local
state, and updates changed module views without running structural layout work on
every live-value message. Semantic control replies and host authorization remain
unchanged. No work, locks, or allocations were added to DSP callbacks.

### Live MixMaster and AuxExpander meters

MindMeld's VU meters are custom OpaqueWidgets, not ModuleLightWidgets. They were
never part of the LED-value protocol. The visitor cached their first painted
panel image; host updates depended on the round-robin native panel renderer.

A precisely audited UI-only overlay exposes the existing peak/RMS levels, hold
values, color themes and meter geometry. The same cubic fader-height mapping is
used. Small shader overlays animate all 25 MixMaster/AuxExpander meters on the
host and visitor without capturing/transmitting new panel images. The original
painted meters are hidden during panel capture to prevent a stale image underneath.
The bridge calls the existing UI peak-hold update once per engine-frame observation;
the module's signal processing is untouched. The overlay is installed idempotently
from `scripts/mixer_meter_overlay.py`, and `tests/source_audit.py` verifies its
exact contents against the pinned upstream header.

### Smaller show updates and less relay work

Rack geometry/artwork descriptions are captured and sent at 5 Hz instead of
20–30 Hz. Small `visual_values` updates carry live meters and controls at the
normal show update rate. The relay retains the last metadata baseline and applies
allowlisted changes immutably, preserving delayed playback snapshots. It does not
expose a new guest write path. Existing scene deltas deliver the resulting values
to visitors. Full scene serialization is lazy: clients using deltas no longer
cause an unused complete scene JSON allocation every relay tick.

### Pace WebRTC packet bursts

The initial RTP sender dropped a packet whenever an earlier asynchronous send was
still in flight. Short encoder bursts could therefore lose otherwise valid audio.
It now retains up to six packets per source and paces them at 20 ms intervals.
This bounds queued work to about 120 ms and drops old work only on actual overload.
RTP sequence numbers account for such drops. A regression test verifies that a
five-packet burst survives asynchronous sending in order. This does not fix ICE
connectivity; the user's connection still needs a reachable TURN path if direct
negotiation fails.

Audio bitrates, authoritative DSP, panel artwork resolution, environment meshes
and cable detail were not reduced for these optimizations. Meter overlays are
vector/shader presentations of live values rather than streamed panel pixels.

## Measurements and verification

Local native benchmarks used disposable engine settings. Local model identification and the native benchmark used a disposable copy of
the saved patch. Reported public acceptance results use `examples/show-mixer-stress.json`, a fresh repository-owned fixture.

| Fixture | Full poll median | Live poll median | Unchanged full/live reply |
|---|---:|---:|---:|
| 16-module saved mixer patch | 8.91 ms | 2.38 ms | 342,187 / 193 bytes |
| 64 synthetic VCO modules | 9.71 ms | 2.09 ms | 327,079 / 193 bytes |

The mixer live-call reduction is about 73%. This is native owner-thread call time,
not total frame time or WAN latency. The 193-byte case is an unchanged poll; active
meters generate larger deltas, and periodic full descriptions still occur.
Reports: `reports/mixer-live-state-benchmark.json` and `reports/live-state-benchmark.json`.

The synthetic graphical test asserts 25 host meters and verifies that shader
levels actually change. Real Chromium decoded two WebRTC audio tracks, with
nonzero waveform energy and roughly 53–72 ms mean jitter buffering on a local
media route; public HTTPS was used only for signaling. This is not WAN validation.

The public buffered test, starting with a 2.5-second buffer, observed 3,594 Opus
packets, 25 meters, 374 changing meter snapshots, no source frame gaps, no decoder
errors and no silent blocks out of 25,355 rendered blocks. Its maximum packet gap
was 141 ms. It includes animated scenery and a deliberate 700 ms host UI stall.
This finite VM/worklet test cannot promise uninterrupted playback on every network
or measure physical phone/Mac output. See `reports/optimized-buffered-audio.log`.

The optimized runtime is prepared separately in `dist/embedded-0.6-optimized-20261021`.
After validation the existing 0.6 launcher selects it through its runtime pointer.
Personal settings/patches and the preserved 0.5 runtime are not replaced.

Run `node --test *.test.mjs` in `show-web`, `scripts/benchmark_live_state.py` for
native measurements, and the existing `scripts/check_show.py --controls` and
`--opus --visual-stage` integration checks. Cross-network WebRTC acceptance remains
blocked on establishing a working direct or TURN route; it must not be inferred
from a successful local WebRTC test.

The additional 80 ms initial-buffer public fallback test **failed** the 2%
silence gate: 704 silent blocks out of 27,136 (about 2.59%), with 126 ms maximum
packet gap and no source-frame discontinuities. Meters continued changing. This
mode is not validated for stable collaborative playing; the optimized source path
is not a substitute for fixing the reported WebRTC connection failure.

All 94 web/relay regression tests pass. The native control integration also passed
gestures, bounded continuous updates, momentary buttons, cable connect/move/remove
and held-button disconnect cleanup. The recursive source audit confirms the
reviewed UI-only mixer overlay and unchanged module DSP. The existing 0.6 launcher
now selects the optimized preview. The prior pointer is retained privately for
rollback. No TURN endpoint was configured by this optimization pass.
