# 0.6 interface update — 21 October 2026

The existing interfaces accumulated unrelated controls in long panels. This
update groups the same actions around listening, playing and hosting a session.
It introduces no new networking or permission system and retains one DSP engine.

## Host

The compact desktop toolbar provides Patch, Modules, Frame rack, Settings, Racks
and Live. The settings window has consistent navigation for Session, Audio & MIDI,
Space, Help and Racks. It fits the available Godot canvas and
uses a scrolling content area. Escape closes settings. Desktop movement help is
in Help instead of overlapping the engine status at the bottom of the scene.

Settings → Session starts with the broadcast state, session name, Go live / End
live session, Copy invitation and Open visitor view. Public listing remains an
explicit switch with its access behavior
explained. Collaborator access is next: enable invited performers, choose a
visitor and use Invite to play / Make read-only. Buttons indicate unavailable
actions. The existing host validation, grants and control leases are retained.

Audience/chat, stage additions and stream/monitoring options are separate
collapsible groups. Stage fixtures use a compact grid rather than seven full-width
buttons. Copying an invitation gives feedback that remains visible briefly.
The host theme uses the same restrained charcoal/mint colors as the browser.

## Visitors and collaborators

Entry asks for a name, with optional appearance choices folded away. Enter in the
name field joins the room. The stage opens unobstructed, with a compact status
bar and a bottom dock. Chat, Sound, Play and Room open one panel at a time.
Closing a panel restores focus to its dock button; Escape closes it. H hides or
restores the interface. Movement input resets when opening a panel.

Sound puts enable, local volume/mute and listening quality first. Connection,
buffering and bandwidth diagnostics are expandable. Real-time audio hides the
irrelevant fallback-buffer controls. Volume is a single output gain after the
spatial panners, shared by WebRTC and buffered audio; it does not modify the host
engine, stream bitrate or other listeners' sound.

The Visitor/Collaborator badge reflects actual host-granted permission, not
whether a menu is open. Play explains direct rack interaction; manual control
selectors and fallback response tuning are expandable. Read-only visitors do
not see those action controls. Profile, data saving, movement help and VR entry
are grouped under Room. Chat retains its input and has an unread indicator.

On narrow phones the panel is a bottom sheet above the dock, with safe-area
spacing and scrolling content. The movement stick is out of the way while a
panel is open. Landscape phones use a bounded side panel. No new UI image assets,
fonts, dependencies or rendering effects were added.

## VR

Native VR retains its existing interaction bindings and menu layout, uses the
shared settings sections and updated names, and preserves its larger default
text size. The browser's world-space panel uses the matching palette, Your room
heading and permission badge text. Desktop HTML overlays are hidden during an XR
session. This is a consistency pass, not a replacement of VR interaction.
Physical OpenXR/WebXR headset acceptance remains untested in this session.

## Chat delta correction

The interface acceptance test found that appending chat mutated the array held
by the relay's previous snapshot before replacing it. Delta comparison could
then omit the new message. Chat append now creates a new bounded array without
mutating previous snapshots. A regression test reconstructs successive deltas,
including rollover beyond the 40-message history limit. The browser acceptance
uses a unique message so an old history entry cannot satisfy the check.

## Validation and deployment

- 101 browser/relay regression tests pass, including actual ICE/DTLS/SRTP and
  control permissions, chat delta preservation and output-volume bounds.
- `check-room-interface.mjs` uses a separate local relay and disposable Chrome:
  portrait 390×844, landscape 844×390, desktop 1440×900; actual grant/revoke,
  fresh chat delivery, volume/mute, Escape/focus and interface recovery pass.
- `tests/interface_layout.gd` runs the native synthetic mixer, verifies disabled
  access actions, section selection, window fitting and Escape. Its smaller-window
  bounds use Godot's scaled canvas coordinates; screenshots were visually checked.
- The real native/browser public-route synthetic fixture decoded two tracks
  through forced Cloudflare TURN, with no browser exceptions. The short final
  check reported zero lost packets, about 39 ms RTT and 52–58 ms mean receiver
  jitter buffering. It is an audio regression check, not a new musical-latency
  guarantee or a physical mobile/headset certification.

The separate native frontend is `dist/embedded-0.6-live-layout-20261021`, selected
by `.tools/live-0.6/runtime.json`. Its DSP DLL is unchanged from the optimized
preview. The previous runtime pointer is backed up privately. The preserved 0.5
launcher/build and personal settings are unchanged. Restart the 0.6 launcher and
reload visitor pages so HTML and the hashed browser bundle come from the same
revision. The existing Umbrel proxy needs no change.

## Live and desktop rack layout

The 0.6 launcher prepares the relay but starts offline. Select **Live**, enter a
session name, then **Go live**. The toolbar and VR menu turn red only after the
local room socket and native engine are connected; connecting is neutral. The
name stays fixed during the broadcast. Use **End live session** to stop sharing
while the patch continues playing. Normal 0.5 startup behavior is unchanged.

The session name appears as the heading of every Show Chat Board on the host and
for visitors, including visitors who join later. The relay accepts this optional
field only from the authenticated native host, limits it to 80 characters and
rejects control characters. Private session names are omitted from the public
homepage. Public listing remains a separate switch; public history uses the name.

**Racks → Layout mode** exposes the existing VR rack layout on desktop. Choose a
module from the list (or click its title while layout mode is enabled), add/select
a destination case, and move the module or its row into it. Position fields use
metres; Tilt, Turn and Roll use degrees. Arrange, Stack and Bring in front of me
provide starting layouts. **Frame rack** includes the separated case transforms.
Turn layout mode off to lock placement and play normally. Deleting a populated
case still requires confirmation because it removes its synth modules.

This uses `rack_layout.gd` through a small `desktop_layout.gd` device adapter.
It preserves the same DSP graph, module IDs, cables, layout file and patch `.3d.json`
sidecars. Shared scene capture now reads `host.rack_layout` for both desktop and
VR. It sends the existing case and module transforms rather than a new protocol.

`tests/interface_live_layout.gd` exercises manual startup, blank-name rejection,
connected/red/offline states, board heading, splitting, rotation and layout save /
restore without changing synth coordinates or cables. Its companion
`show-web/check-live-layout.mjs` runs against a separate local relay, checks the
complete named/rotated state on a late visitor, and checks that visitor attempts
to overwrite it are rejected. The previous responsive-window and phone UI checks
also remain applicable. Physical headset interaction still needs acceptance.

Final Live/layout acceptance also decoded both native audio tracks through forced
Cloudflare TURN with zero reported packet loss (about 40 ms RTT). The test used
only `examples/show-mixer-stress.json` and disposable native settings. It does not
replace physical mobile or VR acceptance. Both test relays were stopped, and the
0.5 launcher/engine hashes were checked unchanged.
