# 0.6 visitor response and rendering fixes — 2026-10-20

Use the existing **Launch Cardinal 3D Live 0.6.bat** after closing the previous
performer/launcher. Visitors should reload their room page. The launcher now selects
`dist/embedded-0.6-20261020` through `.tools/live-0.6/runtime.json`; the earlier
0.6 build and 0.5 backup remain available. Autosaves/settings stay in the same 0.6
user directory and are not replaced by this update.

## Response

- Semantic parameter actions use compact native replies. The regular frame poll
  still steps the native scene and captures its snapshot; remote edits no longer
  repeat that full work. Canonical parameter deltas update the shared descriptor
  references before a Show capture can advertise their revision.
- The host advertises a window of three outstanding parameter updates. Begin/end
  and cables remain acknowledgment barriers; the final value drains before release.
  Old hosts default to a window of one. Input coalesces at the existing 50 ms
  spacing, the aggregate 30-command/second limit remains, and queues remain bounded.
- The host queues simultaneous commands and processes one compact action per frame
  instead of rejecting all but the first command arriving in the same frame.
- Unsnapped received knob/slider visuals ease over 35 ms at render rate; local
  provisional motion remains immediate and immutable shared snapshots are preserved.
- Granted performers default to **Responsive - 80 ms buffer**. **Stable - 180 ms**
  remains selectable in Collaborative controls if sound breaks up. Save mobile data
  still uses 300 ms buffering. Ungranted visitors keep their previous audio settings.
  These are playback buffer durations, not total action-to-sound latency.

## Geometry

Cases export their actual native backboard, side cheeks, top/bottom panels and
mounting rails for each row, including bevel dimensions, materials and transforms.
The native hardware supplies primitive metadata so beveled ArrayMesh boxes are not
silently omitted from the export. Static parts are grouped and instanced in the
browser; tiny threaded holes are omitted. Old publishers retain the bounds fallback.
Module panels now have native thickness. Knobs, switch bodies and slider handles use
native dimensions. Composite switches keep the painted native surface and a correctly
sized hit volume instead of an opaque generic round overlay.

Cables use length-dependent 24–64 curve segments and 12 radial sides, follow module
port normals and have metal sleeves/colored boots. All plug sleeves and boots batch
into two instanced draws for the entire rack, with per-instance cable picking.
Unchanged cable geometry is retained.

## Evidence and practical limits

- A synthetic 64-VCO patch: median native parameter call **9.30 ms → 0.071 ms**;
  reply **326,164 → 234 bytes**. This measures owner-thread native calls, not WAN
  latency or total Godot frame time. Source: `scripts/benchmark_control_replies.py`;
  raw report: ignored `reports/control-replies.json`.
- A deterministic 116 ms round-trip simulation: **18 → 41 updates** for the same
  continuous drag; 95th-percentile application gap **120 → 50 ms**. No pipeline
  exceeds three outstanding requests. Source: `show-web/control-latency.test.mjs`.
- Browser tests cover snapping, out-of-order acknowledgments, final-value drain,
  timeouts/revoke, responsive playback, enclosure bounds, dimensions and picking.
- Real Godot/Cardinal tests verify compact-cache freshness, ordered host queues,
  native undo and momentary release. Invited HTTPS/WebSocket routing through Umbrel
  passes continuous movement, buttons, cable connect/move/disconnect and cleanup.
- Audio/visual publishing still passes the UI-stall regression. A browser check
  verifies exported enclosure geometry and direct cable interaction.

Physical headset frame times and different remote internet connections still need
acceptance testing. The lower audio buffer trades jitter tolerance for response;
choose Stable if the connection produces dropouts.
